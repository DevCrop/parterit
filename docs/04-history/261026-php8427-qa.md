# PHP 8.4.27 보안 업데이트 및 재검수 — 2026-10-26

## 결과와 적용 규칙

PHP 8.4.27 격리 환경에서 기능·PC/모바일 QA를 완료했다. #16에 따라 요구·영향·8개 계획을 patch-notes에 먼저 기록하고 검증 후 문서를 갱신했다. #2의 기존 ImageHelper 래퍼와 #9의 기존 레거시 에디터 접근 차단을 유지했다. 이번 패치에 새 API·화면·DB 변경은 없다.

## 실제 확인한 파일 및 영향

- Backend: dockerfile의 기본 이미지를 8.4.27-apache로 고정. composer.json/lock의 최소 PHP와 solver 기준을 8.4.27로 동기화. config/php-security.ini를 PHP 초기 conf.d로 로드한다. ImageHelper·공통 bootstrap·.htaccess·.user.ini·apache.conf를 확인했다.
- Frontend: resource/dist의 기존 수정·삭제 6건은 사용자 작업으로 보존하고 패키지에서 제외했다. 새 HTML/CSS/JS 변경 없음. 기존 고객사례와 소개서 폼의 실제 화면만 검증했다.
- Data: 기존 partnerit-phpqa-20261015 격리 DB/volume/uploads를 재사용해 QA 데이터만 CRUD했다. 운영 DB·스키마 변경 및 신규 SQL 없음.
- i18n: 고객 문구·언어 키·라벨 변경 없음.
- Test: scripts/check-php-compat.php의 PHP 최소 버전 및 upload progress 설정 검사 보강. 기존 http-check/extras/final-http harness를 8.4.27 1버전과 새로운 로그 경로에 맞춰 재사용했다. fixture용 예전 v2 runtime 모드는 실행하지 않았다.
- Docs: server-spec, requirement-changes, patch-notes 및 본 검수 기록.

## 런타임과 공식 근거

- 실제 이미지: php:8.4.27-apache, manifest digest `sha256:c6527b06c772a2c3cae648ce58c23a2a12ed2fed41cdfb0619ea64be008cc601`.
- CLI PHP 8.4.27, Zend 4.4.27. 개발/운영 모드의 실제 HTTP 요청도 PHP 8.4.27 / apache2handler로 확인했다.

## 전달 범위와 남은 확인

최종 ZIP의 upload/에는 이전 PHP 전환 런타임 11파일과 새 vendor 전체를 누적 제공한다. server-settings/php-security.ini는 호스팅 담당자가 실제 PHP 설정 위치에 적용해야 한다. 파일 업로드 자체가 호스팅 PHP 엔진을 업데이트하지 않는다. .env/DB/uploads/프런트 dist/QA fixture/계정/로그/캡처/개인키는 포함하지 않는다.

운영 소스/vendor/PHP 설정을 먼저 백업하고 PHP 8.4.27 이상 8.4.x와 소스/vendor를 함께 전환한다. 기존 vendor는 혼합하지 않고 전체 교체한다. 워커 재시작 후 실제 웹 SAPI 버전·ini값과 핵심 기능을 확인한다. 실패 시 소스/vendor/PHP 설정을 함께 이전 백업으로 복구한다. 실제 호스팅, PHP-FPM, SMTP 및 Imagick은 이번 검증 대상이 아니다. Git push·실서버 접속/배포 없음.
